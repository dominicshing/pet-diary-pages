Licence, source and build information for the open-source media components used by Pet Diary 1.0.0.

Media components

Pet Diary uses the following open-source components for on-device media inspection, audio processing and slideshow-video creation:

  • FFmpeg 8.1.2—libavcodec, libavdevice, libavfilter, libavformat, libavutil, libswresample and libswscale—copyright the FFmpeg project contributors.
  • FFmpegKit and ffmpeg_kit_flutter_new_min 3.6.2, which provide the native and Flutter interfaces used by Pet Diary.

FFmpeg reports that it is provided under the GNU Lesser General Public License, version 3 or later (LGPLv3+). FFmpegKit and the Flutter package provide the GNU Lesser General Public License, version 3 (LGPLv3). Pet Diary's iOS build uses the package's non-GPL min variant.

The shipped FFmpeg configuration does not contain --enable-gpl or --enable-nonfree. The native FFmpeg and FFmpegKit libraries are packaged as separate dynamic frameworks; the package's Flutter and Objective-C binding code is compiled into the App.

LGPL-covered components are provided without warranty to the extent permitted by law. Nothing in Pet Diary's terms is intended to restrict modification of those components or reverse engineering undertaken to debug modifications where the LGPL permits it.

Build and replacement guidance

The package's scripts/setup_ios.sh downloads the iOS reference archive, removes bitcode, separates its iOS device slice, and packages each library as an XCFramework.

Configure information embedded in the distributed libraries reports an arm64 iOS build using FFmpeg 8.1.2, shared libraries, --enable-version3, --enable-shared, --disable-static, --enable-videotoolbox, --enable-avfoundation, --enable-zlib, --disable-programs and --disable-doc. It does not report GPL or nonfree enablement. A line-wrapped, duplicate-normalized copy of the full embedded configure options is included in the App-bundled OPEN_SOURCE_NOTICES.txt.

An interface-compatible modified native build can be tested by replacing the LGPL-covered frameworks in a development copy of the App, rebuilding or re-signing that copy with Xcode, and installing it with the developer's own Apple signing identity. Apple platform signing and installation rules still apply; Pet Diary does not provide Apple signing credentials.

This native-framework guidance does not by itself provide relinking materials for the Flutter and Objective-C binding code compiled into the App.
